# DevArchitect AI v0.2.0 — Foundation Complete

## Overview

This is DevArchitect AI's first official release. It closes out the
Foundation phase (Milestones 0-2): a working, local-first CLI backed by
a deterministic, evidence-based rule engine, plus the complete
foundational documentation and governance structure that will guide
every release after it.

DevArchitect AI scans a software repository and produces a transparent
engineering health score — no account, no server, no network connection
required. Every number it reports can be traced back to specific,
verifiable evidence. See [README.md](../../README.md) for a full
introduction.

## Highlights

- **Deterministic engineering score.** 17 built-in rules across 7
  categories (Documentation, Testing, DevOps, Repository Hygiene,
  Security Foundations, Architecture Foundations, AI Readiness), scored
  with no hidden weighting — every point traces to a named rule and
  named evidence.
- **Two report formats.** A human-readable terminal report by default;
  `--format json` for machine consumption, with `--output <file>` to
  write either to disk.
- **Local-first, read-only, always.** Analysis never writes to, executes
  code from, or transmits the contents of the repository it scans.
- **A governed, documented foundation.** Vision, philosophy, design
  principles, a decision hierarchy, a governance model, an official
  glossary, and an RFC process — not just code.
- **RFC-001 (Engineering Policies), Accepted.** The design for
  Milestone 3 — organization-defined policies and compliance evaluation
  — is approved and ready to guide implementation.
- **CI confirmed operational.** GitHub Actions runs format, vet, test,
  and build checks on every pull request to `master`.

## Architecture

DevArchitect AI is a five-stage pipeline, not a monolith: scan
(`internal/detector`) → evaluate (`internal/rules`) → orchestrate
(`internal/analyzer`) → aggregate (`internal/scoring`) → render
(`internal/report`), connected by plain Go values, never global state.
`internal/domain` holds the shared vocabulary (`Repository`, `Rule`,
`Finding`, `AnalysisReport`) with no dependencies of its own, which is
what makes every other package safe to depend on it.

Full diagrams (data flow, package dependency graph, and the
`devarchitect analyze` sequence) live in
[docs/architecture/overview.md](../architecture/overview.md); the exact,
enforced dependency contract for every package is in
[docs/architecture/components.md](../architecture/components.md).

## Engineering

- 17 rules across 7 categories — see the full table in
  [README.md](../../README.md#rules-and-categories).
- Score = earned points over applicable points, normalized to 0-100, at
  both the category and overall level — never a hidden weighted average.
  `skipped` and `error` findings are excluded from that math but are
  always visible in the report, never hidden.
- Recommendations come only from failed rules, ordered by impact, then
  by the rule's max score, then by rule ID — deterministic and
  explainable, every time.
- Five ADRs (`docs/adr/ADR-001` through `ADR-005`) record the
  foundational technical decisions: Go and zero dependencies,
  deterministic-before-AI, local-first/read-only analysis, the modular
  rule engine, and the transparent scoring model — including the
  alternatives that were considered and rejected for each.

## Documentation

A complete documentation set now lives under `docs/`:

- **Vision** — what DevArchitect AI is, who it's for, what it explicitly
  does not try to be, and the principles that must never be broken.
- **Philosophy & Design Principles** — the ten values (Local First,
  Privacy First, Deterministic Before AI, and others) and the code-level
  rules that implement them.
- **Glossary** — precise, official definitions for every core term
  (Rule, Finding, Evidence, Category, Score, and more), including the
  Rule vs. Policy and Score vs. Compliance distinctions Milestone 3
  depends on.
- **Architecture** — the system's shape, with diagrams, and the exact
  contract between every package.
- **Engineering standards** — coding standards, testing strategy, and
  the pull request process.
- **Product** — personas and real use cases this tool is built to serve.
- **CLAUDE.md** — the operating manual for anyone, human or AI,
  implementing change in this project.

## Governance

This release establishes how DevArchitect AI makes decisions, not just
what it's built: a documented decision hierarchy (Vision → Philosophy →
Roadmap → RFC → ADR → Implementation → Tests/Documentation), a
governance model defining roles, decision process, and RFC approval
states, and a working RFC process — proven by
[RFC-001: Engineering Policies](../rfc/RFC-001-engineering-policies.md),
now **Accepted** by the Architecture Review Board and ready to govern
Milestone 3's implementation.

## Testing

Test coverage exceeds 95% overall, at or near 100% in the packages that
matter most for trust: `internal/rules`, `internal/scoring`, and
`internal/analyzer`. The full suite runs clean under the race detector.
See [docs/engineering/testing.md](../engineering/testing.md) for the
strategy and coverage policy behind these numbers.

## Continuous Integration

GitHub Actions is confirmed operational. The CI workflow originally
targeted the wrong default branch (`main` instead of this repository's
actual default branch, `master`), so it had never executed. The issue
was corrected in a later maintenance change, and GitHub Actions has now
been successfully validated — every pull request targeting `master` runs
formatting, vet, test, and build checks automatically.

## Known Limitations

- `.devarchitect.yml` configuration and Engineering Policies are
  designed (RFC-001, Accepted) but not yet implemented — no
  organization-specific policy enforcement or CI-friendly compliance
  exit codes exist yet.
- `TEST-002` (test automation exists) checks that test files and a CI
  configuration both exist; it does not parse the CI configuration to
  confirm it actually invokes the tests.
- `DEVOPS-001` (CI configuration exists) and `ARCH-001` (ADRs exist)
  require at least one file inside the recognized directory — an empty
  directory is treated as not present.
- No AI-assisted features exist yet; `domain.AIProvider` is a reserved
  interface with no implementation (Milestone 6).
- `SECURITY.md` and `CODE_OF_CONDUCT.md` do not exist yet — both are
  flagged honestly in this project's own governance documentation and in
  its own self-analysis (`SEC-001` currently fails when DevArchitect AI
  analyzes itself).
- The CLI's version number (`internal/version.Version`) is updated by
  hand as part of each release, per
  [CLAUDE.md](../../CLAUDE.md#release-process) — there is no build-time
  injection (e.g. via `-ldflags`) yet; adding one is future work, not a
  defect in this release.
